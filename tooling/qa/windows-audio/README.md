# Windows WASAPI loopback qualification

This directory is the Todo 21 native qualification boundary. Linux checks cannot qualify it, and Renderer help output, fixture backends, screenshots, synthetic samples, or caller-provided receipts are never native evidence.

The release workflow exposes `authorize_windows_audio`, an explicit default-false input. False authorization runs only the Ubuntu pending lane. True authorization selects the protected environment and the exact scheduling labels `[self-hosted, windows, x64, jastreamer-audio]`. Runtime label validation is order-independent and accepts runner-name/group labels in addition to all four required labels. `JASTREAMER_QA_ENDPOINT_ID` comes only from the protected environment and receipts retain only its SHA-256 digest.

The hosted candidate job stages the signed Renderer diagnostic ZIP, native probe, complete scenario-driver archive, Server peer executable/input, and deterministic media fixtures. It records separate Renderer, probe, driver, Server-peer executable/input, media archive/manifest, source, contract, peer-set, and candidate digests. The physical job downloads these artifacts and never invokes a compiler. `provision.ps1` verifies every digest before process or device mutation, generates an ephemeral TLS certificate and bearer, sends the bearer to Renderer over stdin, and transfers finalization to a cleanup gate that removes temporary credentials/captures before stamping, validating, or writing a qualified receipt. Cleanup deletion errors propagate and cannot leave qualified output.

The bound driver owns evidence creation. It launches the exact extracted Renderer, loopback probe, and TLS WebSocket/HTTP Server peer. Every state, protocol, and capture subscription is installed before its mutation and uses a bounded abort signal. Provisioning reserves one nonzero loopback port; every Server-peer restart binds that same origin so the live Renderer reconnects without being restarted. It drives FLAC, MP3, Vorbis, Opus, and WAV; play/pause/resume/seek/stop; absent, exclusive-busy, invalidated, and restored endpoints; duplicate/conflicting commands; revocation; Server and Renderer restarts; all four acknowledgement/result disconnect cuts; corrupted/truncated media; and cleanup. WASAPI service invalidation is restricted to the dedicated authorized runner and waits on exact Windows service states rather than elapsed time.

The loopback probe captures the selected render endpoint in shared event-driven mode and normalizes interleaved samples to f32. It also opens a bounded exclusive stream for the busy-endpoint case. Capture readiness is emitted only after WASAPI starts, so playback mutation cannot race capture initialization.

Without authorization, the schema-valid result is `qualification_status: "awaiting_external_authorization"`, `PRODUCT_GATE_REQUIRED`, and zero network/audio/external mutation. Native execution remains pending until the protected runner is explicitly authorized and available.
