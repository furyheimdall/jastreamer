Self-hosted music player v0.2.4

Play from any screen.
Hear it where you choose.

jastreamer is a carefully designed player for the music on your own Linux or Windows Server. Queue and control it from any computer or phone on your private LAN, and the Server plays to the output you pick — a USB DAC on this device, a UPnP/DLNA, Google Cast or AirPlay receiver across the room, or experimental, default-off RAAT.

The Player

Every control you reach for, right where you expect it.

The player stays with you in every view and shows what is playing and where. Every computer and phone drives the same Server queue, so moving from the desk to the couch never means rebuilding what you were listening to.

  • Transport that follows the output

    Play/Pause, Stop, Previous, Next and a seek bar. Commands go to the Server, which drives the selected output; seeking is offered where that output supports it.

  • Shuffle and repeat, shared

    Sequential / Shuffle and Repeat off / all / one apply to the shared queue on every device. Shuffle plays a random order without scrambling the list you see, and Play next stays next.

  • A queue you can edit mid-song

    Play next, Add to queue end, or remove any entry — even the one playing — without interrupting the music. Order and duplicates are kept, and the queue survives Server restarts without playing by itself.

  • Outputs inside the player

    Choose the Output device while stopped, use Find output devices again after switching a receiver on, pair AirPlay with its PIN, and set Local volume for this device without touching system volume.

  • Know what you are hearing

    Track information shows codec, sample rate, bit depth, channels and play count. Native exclusive or direct-USB output can show Bit-perfect or Not bit-perfect; qualifying UPnP, Cast and RAAT streams can show Bit-perfect · Server delivery. The scopes differ — see what each badge covers.

On your phone

iPhone and Android phone browsers switch to a four-tab layout automatically. The compact player keeps Play/Pause, Stop and Playback modes under your thumb; expand it for seek, Previous/Next, shuffle, repeat and output selection. Controls are at least 44×44 pixels, and changing tabs collapses the player without stopping the music.

The Android app adds system media controls, direct USB output to a DAC for Server playback, and an offline Saved music library. The native iOS client is controller-only and available as source and CI builds only.

How listening works

Your phone is the remote. The Server plays the music.

Every jastreamer screen is a controller. It sends commands to one Server, which owns the library, the queue and the selected output and streams to that output itself. For network listening, the audio never detours through the phone in your hand.

  1. Controller

    A browser, the desktop app or a phone. Browses the library and sends Play, Pause, Next, Seek and output choices.

  2. Server

    Your Linux or Windows machine. Keeps the library, the one shared queue and playback state, and sends audio to the one selected output.

  3. Output

    Where sound comes out: This device — speakers or a USB DAC on the computer or phone you are using — or a network receiver.

Close listening: a USB DAC on this device

Select This device on the computer or Android phone your DAC is plugged into. The Windows and Mac apps can opt in to native WASAPI or CoreAudio output, and the Android app to experimental direct USB. The Server still owns the queue, so another controller can pause or skip from across the room.

Around the house: network receivers

Select a UPnP/DLNA renderer, a Google Cast device, an AirPlay receiver or, after opting in, a compatible RAAT receiver. The Server streams to it directly, so your phone can lock or close the page and the music keeps playing — pick it up again from any controller.

Supported outputs

  • This deviceThe computer or phone you are using. The Windows, Mac and Android apps add opt-in exclusive or direct-USB output to a DAC.
  • UPnP/DLNABuilt in: discovers and controls renderers on your LAN.
  • Google CastOptional on both Server platforms; off by default.
  • AirPlaySending from the Linux container only, including PIN/password pairing.
  • RAAT · experimentalOff by default on both Server platforms. Needs a compatible receiver and configured FFmpeg. Prerequisites and limits; not Roon Ready certification.

Discovery needs multicast and private-LAN routes between Server, controller and output (SSDP UDP 1900 for UPnP, mDNS UDP 5353 for Cast and AirPlay). Receivers differ — some lack pause or seeking, reject formats or require authentication — so confirm playback and sound on your own equipment.

RAAT, with the same player and queue

An independently implemented, experimental output — off by default, not Roon Ready certification. The Server remains the player; your screens remain controllers, and the receiver never gets a second queue.

Display, control and delivery

  • Supported receiver plugins receive track metadata, a JPEG artwork thumbnail and playback state. Play/Pause, Stop, Previous, Next and Seek use the same Server queue; device-origin control events return to that queue too.
  • PCM retains the original sample rate, channels and precision at unity gain, without resampling, normalization or DSP. Integer widening may add zero-padding; unsupported formats fail instead of silently converting.
  • A continuous audio connection feeds a bounded receiver buffer, with prefill and device-clock scheduling. The queue waits for consumed audio, not just the Server finishing its send. This is not a promise of gapless or synchronized multiroom playback.

Before enabling. Use a trusted private IPv4 LAN and a compatible protocol-3 receiver that accepts the adapter; signing-key receivers are rejected, not bypassed. Discovery alone does not prove compatibility. RAAT control and audio are not encrypted.

FFmpeg is required. The Linux container bundles it. Windows Server needs a separately installed compatible FFmpeg, configured with its absolute executable path and the required input protocol, decoder and PCM encoders. In Settings → Playback & outputs, enable RAAT, save and restart. Read the RAAT prerequisites first.

Qualification is limited. FiiO K17 full-track and transport checks, and Next/Stop checks on a receiver advertising FiiO R7, are not audible-output, physical-button or DAC verification. They do not establish general hardware compatibility. See the RAAT guide and evidence limits.

Signal-path badges, with their limits spelled out

A native output badge and a Server delivery badge describe different parts of the path. Neither certifies the sound at a physical DAC. Selecting a badge shows its evidence and boundary without changing playback.

Native output: where it is available

  • Windows 10/11 app — Windows native backend with Exclusive on (WASAPI Exclusive); confirm the actual path on your own Windows audio hardware. Windows audio guide
  • Apple Silicon Mac app — CoreAudio backend with Exclusive on, to a USB DAC; hardware-tested so far with one DAC (FIIO M33R2R on macOS 26.6.2). macOS audio guide
  • Android app — USB bit-perfect (direct USB) to a USB Audio Class DAC for Server playback on the phone; Saved music keeps the standard Android output. An experimental option shown after turning on Settings → General → Experimental features. Android guide

The native badge reads Bit-perfect only when

  • the source is lossless and the Server reports it untransformed;
  • sample rate, channels and precision are unchanged (zero-padding into a wider container keeps the original bits);
  • app volume is at 100% — exclusive and direct-USB modes fix it there, so set the level on your DAC or amplifier;
  • the exclusive or direct-USB path is actually running, not just requested.

While that native path is active, an altered signal is reported as Not bit-perfect with the reason. Merely selecting the mode does not earn a badge.

Native output scope. The badge describes jastreamer’s application path only. It does not verify the driver, DSP inside the DAC, or physical output — check the negotiated path on your own hardware.

Bit-perfect · Server delivery. Requires a known lossless source and evidence for the current track and output. For UPnP and Cast, the Server must have started delivering the inspected original file bytes without transformation. For RAAT, the active, owned stream must have accepted PCM at the original rate and channels with precision preserved, unity gain and no DSP. Underrun or overrun evidence removes RAAT qualification.

Delivery is not DAC transparency. Receiver volume, DSP, mixing, resampling and conversion remain unverified. Original-file delivery does not prove a negotiated receiver PCM format; the badge is not a physical bit-transparency or certification claim.

No qualifying badge. Browser audio (including the PWA and Linux desktop), shared or system output, and AirPlay do not receive these badges. Merely selecting an output or avoiding resampling is not enough. Signal-path guide

Your library

A music library that lives on your network, not in someone else’s cloud.

jastreamer plays only local files you own. The Server keeps the state; every browser, desktop app and phone shows the same Server-hosted interface.

  • Scans without touching your files

    FLAC, MP3, WAV/WAVE, Ogg/Vorbis, Opus and M4A from a read-only library. Scan now reuses saved results for unchanged files; a confirmed Full rescan rereads everything.

  • Browse the way you think

    Tracks, albums, artists, genres and folders with embedded artwork and search. Folder actions apply to every matching track in subfolders.

  • Playlists for every device

    Build playlists on the Server and queue them from any computer or phone with Play all, Play next or Add to queue end.

  • Likes and Most Played

    Server-wide likes and play counts, a Most Played view, and a one-time Shuffle liked into queue action. Counts live in the database, never in your file tags.

  • Checks every file end to end

    Background audio verification with a filterable error and file-check history that you can export as CSV.

  • Accounts on your terms

    First-account setup, password login, change and recovery, durable sessions, and an optional built-in HTTPS listener with your own trusted certificate.

Setup

From release to first track in four steps.

The Server needs writable config and data folders and read-only access to your music. Details for each platform are in the install guide.

  1. Pick and verify

    Choose a release and verify its checksums or image digest.

  2. Install the Server

    On Linux or Synology or Windows, with your music root read-only.

  3. Create your account

    Open the Server’s LAN URL, create the first account privately, set the music folder and run Settings → Library → Scan now.

  4. Pick an output and play

    Select an output, play a track and confirm you hear it. Everyday controls are in the user guide.

Know the limits

What jastreamer is not.

Clear boundaries keep your music, your network and your expectations safe.

  • Not an Internet service

    It is designed for a trusted private LAN and must not be exposed publicly. Plain LAN HTTP encrypts neither credentials nor audio; use the built-in HTTPS listener where that matters.

  • Not a cloud or subscription

    It plays only local files you own and never modifies them. There is no telemetry, analytics, update check or externally hosted content.

  • Not a media server for other apps

    It discovers and controls UPnP/DLNA renderers and serves media to them; it is not a DLNA library for third-party players.

  • Not an offline browser player

    The PWA has no library cache. Offline listening exists only in the Android app’s Saved music.

  • Not self-updating or app-store software

    There is no in-app updater, Windows service or app-store listing. Download and verify each update yourself; Server updates keep your data.

  • Not a multiroom or phone-relay system

    The Server plays to one selected output at a time; there is no synchronized multiroom playback. For network outputs the phone only sends commands — audio goes from the Server to the receiver.
