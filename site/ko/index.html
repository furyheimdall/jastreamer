플레이어

책상에서도 소파에서도, 같은 곡과 같은 대기열.

컴퓨터와 휴대전화는 Server가 가진 플레이어 하나를 함께 조작하는 리모컨입니다. 두 화면이 같은 대기열과 같은 선택 출력을 제어하므로, 책상에서 소파로 옮겨도 듣던 목록을 다시 만들 필요가 없습니다.

  • 출력에 맞춘 재생 제어

    재생/일시 정지, 정지, 이전 곡, 다음 곡과 탐색 막대. 명령은 Server로 가고 Server가 선택한 출력을 구동하며, 탐색은 그 출력이 지원할 때 제공됩니다.

  • 함께 쓰는 랜덤·반복

    순차 재생 / 랜덤 재생과 반복 없음 / 전체 반복 / 한 곡 반복은 모든 기기의 공용 대기열에 적용됩니다. 랜덤 재생은 보이는 목록을 뒤섞지 않고 무작위 순서로 재생하며, 다음 순서에 추가한 곡은 계속 다음 순서를 지킵니다.

  • 곡이 흐르는 중에도 고치는 대기열

    다음 순서에 추가, 대기열 끝에 추가는 물론, 지금 재생 중인 곡을 포함한 어떤 항목이든 음악을 끊지 않고 삭제할 수 있습니다. 순서와 중복 곡을 유지하며, Server를 재시작해도 대기열이 남고 저절로 재생되지는 않습니다.

  • 플레이어 안에서 고르는 출력

    정지 상태에서 재생 기기를 고르고, 수신기를 켠 뒤에는 재생 기기 다시 찾기를 누르세요. AirPlay는 PIN·암호로 페어링하고, 로컬 음량은 시스템 음량을 건드리지 않고 이 기기만 조절합니다.

  • 지금 듣는 소리를 정확히

    곡 정보에서 코덱, 샘플 레이트, 비트 깊이, 채널, 재생 횟수를 확인할 수 있습니다. 네이티브 독점·USB 다이렉트 출력에는 비트 퍼펙트 또는 비트 퍼펙트 아님이, 조건을 충족한 UPnP·Cast·RAAT 스트림에는 비트 퍼펙트 · 서버 전송이 표시될 수 있습니다. 각 배지가 뜻하는 범위 보기

  • 휴대전화에서

    iPhone·Android 휴대전화 브라우저에서는 네 탭 화면을 사용합니다. 작은 플레이어에서 재생/일시 정지, 정지, 재생 모드를 바로 조절하고, 펼치면 탐색, 이전·다음 곡, 재생 기기 선택이 나타납니다. 다른 탭으로 옮겨도 재생은 계속되고 플레이어만 접힙니다.

    Android 앱은 시스템 미디어 제어, Server 재생용 실험 기능인 USB 다이렉트 출력, 오프라인 보관함 저장된 음악을 더합니다. USB 다이렉트는 설정에서 켜서 사용합니다. 네이티브 iOS 앱은 제어 전용이며 소스와 CI 빌드로만 제공됩니다.

듣는 방식

휴대전화는 리모컨, 음악은 Server가 재생합니다.

jastreamer의 모든 화면은 컨트롤러입니다. 화면은 명령을 Server 하나에 보내고, 보관함·대기열·선택한 출력을 가진 Server가 그 출력으로 직접 음원을 보냅니다. 네트워크로 들을 때 오디오는 손에 든 휴대전화를 거치지 않습니다.

  1. 컨트롤러

    브라우저, 데스크톱 앱, 휴대전화. 보관함을 탐색하고 재생·일시 정지·다음 곡·탐색과 출력 선택 명령을 보냅니다.

  2. Server

    내 Linux·Windows 컴퓨터. 보관함, 하나뿐인 공용 대기열, 재생 상태를 보관하고 선택한 출력 하나로 오디오를 보냅니다.

  3. 출력

    실제로 소리가 나는 곳입니다. 지금 쓰는 컴퓨터나 휴대전화의 스피커·USB DAC인 이 기기, 또는 네트워크 수신기입니다.

가까이에서: 이 기기의 USB DAC

DAC을 연결한 컴퓨터나 Android 휴대전화에서 이 기기를 고르세요. Windows·Mac 앱은 WASAPI·CoreAudio 네이티브 출력을, Android 앱은 실험 기능인 USB 다이렉트 출력을 선택해 쓸 수 있습니다. 대기열은 여전히 Server가 가지므로 방 건너편의 다른 컨트롤러로 일시 정지하거나 다음 곡으로 넘길 수 있습니다.

집 안 어디서나: 네트워크 수신기

UPnP/DLNA 재생 기기, Google Cast 기기, AirPlay 수신기 또는 기능을 켠 뒤 호환되는 RAAT 수신기를 고르세요. Server가 수신기로 직접 스트리밍하므로 휴대전화를 잠그거나 페이지를 닫아도 음악은 계속되고, 어느 컨트롤러에서든 다시 이어서 제어할 수 있습니다.

지원 출력

  • 이 기기지금 쓰는 컴퓨터나 휴대전화. Windows·Mac·Android 앱은 DAC으로 보내는 독점·USB 다이렉트 출력을 선택해 쓸 수 있습니다.
  • UPnP/DLNA기본 제공. LAN의 재생 기기를 찾아 제어합니다.
  • Google CastLinux·Windows Server에서 선택해 쓰며 기본값은 꺼짐입니다.
  • AirPlayLinux 컨테이너에서만 전송하며 PIN·암호 인증을 지원합니다.
  • RAAT호환 RAAT 수신기로 음악과 앨범 아트를 보내고 공용 대기열로 제어합니다. 설정에서 켜서 쓰는 실험적 전송 기능입니다. RAAT 사용 안내

수신기는 사설 LAN에서 Server와 통신하고 멀티캐스트로 검색될 수 있어야 합니다. 네트워크 요구 사항을 확인하세요. 지원 형식과 제어 기능은 수신기마다 다릅니다.

오디오 경로가 보존하는 것을 확인하세요

네이티브 출력 배지와 서버 전송 배지는 서로 다른 경로 구간을 설명합니다. 배지를 선택하면 현재 곡과 출력의 근거를 확인할 수 있습니다.

배지 표시 예시

예시 상태로 렌더링한 실제 플레이어 UI이며, 하드웨어 검증 화면은 아닙니다. 이미지를 선택하면 확대됩니다.

네이티브 출력: 사용할 수 있는 곳

  • Windows 10/11 앱 — WASAPI 독점 모드. 실제 Windows 오디오 장비에서의 동작은 미검증입니다. Windows 오디오 안내
  • Apple Silicon Mac 앱 — CoreAudio 백엔드에서 독점 모드를 켜고 USB DAC으로 출력. 하드웨어 검증은 아직 DAC 한 대(macOS 26.6.2의 FIIO M33R2R)뿐입니다. macOS 오디오 안내
  • Android 앱 — 휴대전화의 Server 재생을 USB 오디오 클래스 DAC으로 보내는 USB 비트 퍼펙트(USB 다이렉트). 저장된 음악은 계속 표준 Android 출력을 사용합니다. Settings → 일반 → 실험 기능을 켜야 나타나는 실험 기능입니다. Android 안내

네이티브 배지가 비트 퍼펙트로 표시되는 조건

  • 무손실 원본이며 Server가 미변환으로 보고함
  • 샘플 레이트·채널·정밀도가 그대로임(더 넓은 컨테이너에 0을 채워 담아도 원본 비트는 유지됨)
  • 앱 음량 100% — 독점·USB 다이렉트 모드에서는 100%로 고정되므로 음량은 DAC이나 앰프에서 조절
  • 독점·USB 다이렉트 경로가 요청만 된 것이 아니라 실제로 동작 중임

해당 네이티브 경로가 동작 중이지만 신호가 바뀌었다면 비트 퍼펙트 아님과 그 이유를 표시합니다. 모드를 선택하기만 한 상태에 배지를 붙이지 않습니다.

서버 전송. 알려진 무손실 원본과 현재 전송 근거가 필요합니다. UPnP·Cast는 검사한 원본 파일을 변환 없이 전달해야 합니다. RAAT는 원래 레이트·채널·정밀도의 PCM을 이득 1, DSP 없이 받아들여야 하며, 언더런·오버런이 있으면 자격을 잃습니다.

배지의 범위. 네이티브 배지는 jastreamer 애플리케이션 경로를, 서버 전송 배지는 Server가 내보내는 스트림을 설명합니다. 수신기 내부 처리·드라이버·물리적 DAC 출력까지 검증하지는 않습니다. 브라우저 오디오, 공유·시스템 출력, AirPlay에는 적용되지 않습니다. 신호 경로 안내

내 보관함

남의 클라우드가 아니라 내 네트워크에 있는 음악 보관함.

jastreamer는 사용자가 보유한 로컬 파일만 재생합니다. 상태는 Server가 보관하고, 모든 브라우저·데스크톱 앱·휴대전화가 Server가 제공하는 같은 화면을 표시합니다.

  • 원본은 건드리지 않는 스캔

    읽기 전용 보관함의 FLAC, MP3, WAV/WAVE, Ogg/Vorbis, Opus, M4A를 스캔합니다. 지금 스캔은 변경 없는 파일의 결과를 재사용하고, 확인 후 실행하는 전체 다시 스캔은 모든 파일을 다시 읽습니다.

  • 원하는 방식으로 탐색

    곡·앨범·아티스트·장르·폴더를 내장 앨범 아트와 함께 탐색하고 검색합니다. 폴더 작업은 하위 폴더의 곡까지 모두 적용됩니다.

  • 모든 기기에서 쓰는 플레이리스트

    Server에 플레이리스트를 만들어 두고 어느 컴퓨터나 휴대전화에서든 전체 재생, 다음 순서에 추가, 대기열 끝에 추가로 대기열에 담으세요.

  • 좋아요와 많이 재생한 곡

    Server 전체에서 공유하는 좋아요와 재생 횟수, 많이 재생한 곡 목록, 한 번만 실행하는 좋아요 섞어 담기. 횟수는 데이터베이스에 저장되며 음악 파일 태그는 바꾸지 않습니다.

  • 파일을 처음부터 끝까지 검증

    백그라운드에서 음원을 검증하고, 필터링할 수 있는 오류·파일 검사 기록을 CSV로 내보낼 수 있습니다.

  • 내가 관리하는 계정

    최초 계정 생성, 비밀번호 로그인·변경·복구, 로그인 상태 유지, 그리고 직접 준비한 신뢰할 수 있는 인증서를 쓰는 선택적 내장 HTTPS.

    아무 최신 브라우저에서 Server의 LAN 주소를 여세요. PWA로 설치하려면 신뢰할 수 있는 HTTPS 주소가 필요하며, 오프라인 플레이어가 아닙니다.

    PWA 안내

설치 전에 검증하세요

모든 자산은 SHA256SUMS에 나열되고, 각 패키지는 릴리즈 페이지에 .sha256 파일과 manifest를 함께 제공하며, release-provenance.json에 소스 리비전과 CI 실행이 기록됩니다.

Android 서명 인증서 SHA-256은 53285C2C239AFF2927EBE6F5C6AEBB82FDBB50956ED84B1E9F0222B2D925943E입니다. 산출물별 서명 상태는 코드 서명 정책을 확인하세요.

설치 흐름

릴리즈부터 첫 곡까지 네 단계.

Server에는 쓰기 가능한 config·data 폴더와 음악에 대한 읽기 전용 접근이 필요합니다. 플랫폼별 세부 절차는 설치 안내에 있습니다.

  1. 고르고 검증하기

    릴리즈를 고르고 체크섬이나 이미지 다이제스트를 검증합니다.

  2. Server 설치

    Linux·Synology 또는 Windows에 설치하고 음악 루트는 읽기 전용으로 연결합니다.

  3. 계정 만들기

    Server의 LAN 주소를 열어 첫 계정을 비공개로 만들고, 음악 폴더를 지정한 뒤 Settings → 보관함 → 지금 스캔을 실행합니다.

  4. 출력 고르고 재생

    출력을 선택해 한 곡을 재생하고 소리를 확인합니다. 평소 조작법은 사용자 안내서에 있습니다.

한계 알기

jastreamer가 아닌 것.

  • 인터넷 서비스가 아닙니다

    신뢰하는 사설 LAN용이며 공용 인터넷에 노출하면 안 됩니다. LAN의 일반 HTTP는 인증 정보도 오디오도 암호화하지 않으므로, 필요하면 내장 HTTPS를 사용하세요.

  • 클라우드나 구독 서비스가 아닙니다

    보유한 로컬 파일만 재생하며 원본을 수정하지 않습니다. 사용 기록 수집, 분석 도구, 새 버전 확인, 외부 콘텐츠 불러오기가 없습니다.

  • 다른 앱을 위한 미디어 서버가 아닙니다

    UPnP/DLNA 재생 기기를 찾아 제어하고 음원을 전달하는 쪽이며, 다른 플레이어용 DLNA 보관함이 아닙니다.

  • 자동 업데이트나 앱 스토어 제품이 아닙니다

    앱 안의 업데이트 기능, Windows 서비스, 앱 스토어 등록이 없습니다. 업데이트는 직접 내려받아 검증하세요. Server 업데이트는 데이터를 그대로 유지합니다.

  • 멀티룸 시스템이 아닙니다

    Server는 한 번에 선택한 출력 하나로만 재생하며 동기화된 멀티룸 재생은 없습니다.
