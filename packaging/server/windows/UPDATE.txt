UPDATING AN EXISTING PORTABLE WINDOWS SERVER

Before stopping, inspect the actual launcher and server.json. Resolve data_dir
and every library root, including external drives, UNC shares and junctions.
Record their actual paths and permissions; do not assume adjacent data/music.
Stop if paths disagree or cannot be read. New-install defaults do not apply.

1. Stop the existing Server with Ctrl+C and wait for its console to close.
2. Back up the complete actual config/data and installation folder, including
   SQLite WAL/SHM files when present. Back up every music root or verify an
   existing current backup/snapshot covering it. Keep backups outside source
   trees, verify contents/checksums and an isolated restore, and record the old
   package identity and coverage. A folder-only backup misses external roots;
   do not replace the package while backup coverage is unknown or unverified.
3. Verify and extract the new ZIP into a separate temporary folder.
4. Replace only package-owned files in the existing folder: the executable,
   launcher, first-install script, template, guidance, project license, notices,
   packaged samples, and third-party licenses. Keep the existing server.json,
   data, music, and any user files. Packaged samples/ is not the music library.
5. Run start-server.cmd from the existing folder and refresh the Web UI. Because
   server.json already exists, the launcher does not copy samples into music.

To opt in to the packaged samples on an existing installation, stop the Server,
choose an approved library root, and copy the five files from packaged samples/
into its jastreamer-samples subdirectory. Retain byte-identical files and stop
if any destination filename has different contents; never replace it.

The launcher detects an existing server.json, validates it, and starts with it
without writing it. It does not reset accounts, migrate or delete existing data,
re-register libraries, or change manually configured library/FFmpeg/helper
paths. Never update while the Server is running. Do not replace the whole folder
with the new extracted folder unless you first restore your existing config and
data into it while the Server is stopped.

This package does not bundle FFmpeg or AirPlay support. Updating it does not add,
remove, or rewrite any manually configured external executable path.
